# Bound owned year craft production after a wealth reserve

The inherited year controller stops adding its wood-craft order once created wealth reaches its target, but the standing order keeps producing. This revision adds a year-only resource policy: pause only the controller's own repeating wood MakeCrafts order once observed created wealth reaches 10,000, and allow the original creation path to resume below 5,000. It retains a reserve above the first progression milestone's wealth requirement and gives other work the capacity that the recurring order used. Ownership and failed-cancellation handling remain explicit.

The policy calls the original progression method until the reserve is reached. It cancels an order only if its observed integer id belongs to this controller's ownership set, its job is MakeCrafts, it repeats, and its material category is wood. An accepted cancellation removes the id from ownership and records the paused state. A refused request leaves ownership and state intact so the normal retry gate applies. While paused, wealth above 5,000 keeps the policy quiet. A fall below 5,000 clears the original one-time creation marker and returns to the original method. Other recipes and unowned orders are retained. The full-year controller owns this change; the managed and midyear controllers retain their parent behavior.

The 10,000/5,000 separation prevents toggling around the upper threshold. The lower threshold is the retained controller's original first-year wealth target. The new upper reserve is a resource-management choice rather than a claim of further rank progress. Native components below 20 population cannot demonstrate a rank gain; the ordinary 20-citizen run supplies a separate observed progression case. Behavior on the lower restart boundary is covered by software checks; none of these completed native cases needed to restart after cancellation.
