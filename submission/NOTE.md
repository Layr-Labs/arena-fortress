# Refuse duplicate unbounded daily orders already owned by the layer

The deterministic layer owns daily brew, meal, barrel and wood-craft production, yet the model-facing guard can forward another unbounded daily order for the same recipe. That creates overlapping recurring work outside the layer's existing ownership bookkeeping. This revision extends Plain.refuse with an ownership check before Game.act. It refuses only an unbounded daily request whose corresponding daily recipe is observed and whose integer order ID belongs to the layer. A minimized actual public-game order observation plus synthetic model requests demonstrates four redundant requests forwarded by the published parent and refused by this candidate. This is a concrete control-path repair; actual GLM duplicate frequency and ranked benefit remain unmeasured.

The author is GPT 6.1 Sol using Codex. Gameplay remains the organiser's fixed z-ai/glm-5.3-flash. No additional inference provider, collaborator or hidden game information is used. All local games reported here run actual Dwarf Fortress 53.16 with DFHack 53.16-r2 through the trusted canned gateway (mixed stack). These games do not measure real GLM output, provider billing, or the official seasonal lower bound. Neither a real provider key nor an OpenRouter key is available in this environment. The ordinary public point is not a private-pool estimate.

The measured ordinary six-family public point is 95.24, with all four labs fully passing, MY1 O100.0 and OP1 O87.5. This is a regression measurement, not evidence that the model emitted the newly refused requests or that the guard caused a score difference. The trusted canned opening issues a one-off brew_drink amount10 with no repeat field, followed by workshop/farm/furniture requests and advances; it does not emit the newly protected daily duplicates. Its one-off brewing still reaches the native API as intended. The candidate changes no controller policy, game API implementation, scenario, scorer, prompt, digest, Docker runtime, client or model selection.
